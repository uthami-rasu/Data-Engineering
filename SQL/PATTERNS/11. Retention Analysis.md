# SQL Pattern 11: Retention Analysis

## 1. What Is Retention Analysis?

Retention analysis answers one simple business question:

> **After a user joins or performs an important action, do they come back later?**

For example, a mobile app gets 100 new users on January 1.

The company wants to know:

```text
How many came back on January 2?
How many came back on January 8?
How many came back on January 31?
```

Those are:

```text
Day-1 Retention
Day-7 Retention
Day-30 Retention
```

---

# 2. Simple Real-World Example

Suppose these users signed up:

| user_id | signup_date |
| ------: | ----------- |
|       1 | 2024-01-01  |
|       2 | 2024-01-01  |
|       3 | 2024-01-01  |
|       4 | 2024-01-01  |
|       5 | 2024-01-01  |

Now their activity is:

| user_id | activity_date |
| ------: | ------------- |
|       1 | 2024-01-01    |
|       1 | 2024-01-02    |
|       1 | 2024-01-05    |
|       2 | 2024-01-01    |
|       2 | 2024-01-03    |
|       3 | 2024-01-01    |
|       3 | 2024-01-02    |
|       4 | 2024-01-01    |
|       5 | 2024-01-01    |
|       5 | 2024-01-02    |

---

# 3. What Is Day-1 Retention?

Day-1 retention asks:

> **Did the user come back exactly one day after signup?**

For our users:

### User 1

```text
Signup     → Jan 01
Returned   → Jan 02
```

YES.

### User 2

```text
Signup     → Jan 01
Returned   → Jan 03
```

NO for Day-1.

### User 3

```text
Signup     → Jan 01
Returned   → Jan 02
```

YES.

### User 4

```text
Signup     → Jan 01
No return
```

NO.

### User 5

```text
Signup     → Jan 01
Returned   → Jan 02
```

YES.

Therefore:

```text
Day-1 retained users = 3
Total users          = 5
```

Retention rate:

```text
3 / 5 × 100 = 60%
```

# 5. Problem Statement

Calculate **Day-1 retention**.

A user is considered retained if they have an activity record exactly:

```text
signup_date + 1 day
```

---

# 6. Step 1 — Find the Day-1 Date

For every user:

```text
signup_date + 1 day
```

Input:

| user_id | signup_date |
| ------: | ----------- |
|       1 | Jan 01      |
|       2 | Jan 01      |
|       3 | Jan 01      |
|       4 | Jan 01      |
|       5 | Jan 01      |

Day-1 date is:

| user_id | signup_date | day_1_date |
| ------: | ----------- | ---------- |
|       1 | Jan 01      | Jan 02     |
|       2 | Jan 01      | Jan 02     |
|       3 | Jan 01      | Jan 02     |
|       4 | Jan 01      | Jan 02     |
|       5 | Jan 01      | Jan 02     |

---

# 7. Step 2 — Check Whether the User Was Active on That Date

We join the user table with activity.

```sql
SELECT
    u.user_id,
    u.signup_date,
    a.activity_date
FROM users u
LEFT JOIN user_activity a
    ON u.user_id = a.user_id
   AND a.activity_date = u.signup_date + INTERVAL '1 day';
```

Expected result:

| user_id | signup_date | activity_date |
| ------: | ----------- | ------------- |
|       1 | Jan 01      | Jan 02        |
|       2 | Jan 01      | NULL          |
|       3 | Jan 01      | Jan 02        |
|       4 | Jan 01      | NULL          |
|       5 | Jan 01      | Jan 02        |

Now it is easy to understand:

```text
activity_date exists → retained
activity_date NULL   → not retained
```

---

# 8. Step 3 — Convert It to YES / NO

```sql
SELECT
    u.user_id,
    u.signup_date,

    CASE
        WHEN a.activity_date IS NOT NULL
            THEN 'YES'
        ELSE 'NO'
    END AS day_1_retained

FROM users u
LEFT JOIN user_activity a
    ON u.user_id = a.user_id
   AND a.activity_date = u.signup_date + INTERVAL '1 day';
```

Output:

| user_id | signup_date | day_1_retained |
| ------: | ----------- | -------------- |
|       1 | Jan 01      | YES            |
|       2 | Jan 01      | NO             |
|       3 | Jan 01      | YES            |
|       4 | Jan 01      | NO             |
|       5 | Jan 01      | YES            |

---

# 9. Why Do We Use LEFT JOIN?

This is extremely important.

We want to keep **all users**, even users who never returned.

Suppose User 4 did not return.

With `LEFT JOIN`:

| user_id | activity_date |
| ------: | ------------- |
|       4 | NULL          |

We can therefore identify:

```text
User 4 → Not retained
```

With `INNER JOIN`, User 4 would disappear completely.

That would make it impossible to calculate the correct retention rate.

So remember:

```text
Retention analysis
+
Need users who did NOT return
=
Usually LEFT JOIN
```

---

# 10. Step 4 — Calculate Retained Users

We need to count users who returned.

```sql
SELECT
    COUNT(*) FILTER (
        WHERE a.activity_date IS NOT NULL
    ) AS retained_users
FROM users u
LEFT JOIN user_activity a
    ON u.user_id = a.user_id
   AND a.activity_date = u.signup_date + INTERVAL '1 day';
```

Output:

| retained_users |
| -------------: |
|              3 |

---

# 11. Step 5 — Calculate Total Users

Total users:

```sql
SELECT COUNT(*) AS total_users
FROM users;
```

Output:

| total_users |
| ----------: |
|           5 |

---

# 12. Step 6 — Calculate Retention Rate

Formula:

```text
Retention Rate
=
Retained Users
/
Total Users
× 100
```

Here:

```text
3 / 5 × 100
=
60%
```

---

# 13. Complete Day-1 Retention Query

```sql
SELECT
    COUNT(*) FILTER (
        WHERE a.activity_date IS NOT NULL
    ) AS retained_users,

    COUNT(*) AS total_users,

    ROUND(
        COUNT(*) FILTER (
            WHERE a.activity_date IS NOT NULL
        ) * 100.0 / COUNT(*),
        2
    ) AS retention_rate

FROM users u

LEFT JOIN user_activity a
    ON u.user_id = a.user_id
   AND a.activity_date = u.signup_date + INTERVAL '1 day';
```

Output:

| retained_users | total_users | retention_rate |
| -------------: | ----------: | -------------: |
|              3 |           5 |          60.00 |

---

# 14. Day-7 Retention

The logic is exactly the same.

Instead of:

```sql
u.signup_date + INTERVAL '1 day'
```

use:

```sql
u.signup_date + INTERVAL '7 days'
```

Query:

```sql
SELECT
    COUNT(*) FILTER (
        WHERE a.activity_date IS NOT NULL
    ) AS retained_users,

    COUNT(*) AS total_users,

    ROUND(
        COUNT(*) FILTER (
            WHERE a.activity_date IS NOT NULL
        ) * 100.0 / COUNT(*),
        2
    ) AS retention_rate

FROM users u

LEFT JOIN user_activity a
    ON u.user_id = a.user_id
   AND a.activity_date = u.signup_date + INTERVAL '7 days';
```

---

# 15. Day-30 Retention

Same pattern again:

```sql
a.activity_date = u.signup_date + INTERVAL '30 days'
```

The important thing is that **only the retention window changes**.

---

# 16. Very Important: Exact Day vs Within N Days

These are different questions.

## Exact Day-7 Retention

Question:

> Was the user active exactly 7 days after signup?

Condition:

```sql
a.activity_date =
    u.signup_date + INTERVAL '7 days'
```

Example:

```text
Signup   → Jan 01
Activity → Jan 08
```

YES.

But:

```text
Signup   → Jan 01
Activity → Jan 05
```

NO for exact Day-7 retention.

---

# 17. Returned Within 7 Days

Different question:

> Did the user return at least once during the first 7 days?

Condition:

```sql
a.activity_date > u.signup_date
AND a.activity_date <= u.signup_date + INTERVAL '7 days'
```

Example:

```text
Signup → Jan 01

Activities:
Jan 03
Jan 05
```

User returned within 7 days.

Even though there was no activity exactly on Jan 08.

---

# 18. Query for "Returned Within 7 Days"

```sql
SELECT
    u.user_id,

    CASE
        WHEN COUNT(a.activity_date) > 0
            THEN 'YES'
        ELSE 'NO'
    END AS returned_within_7_days

FROM users u

LEFT JOIN user_activity a
    ON u.user_id = a.user_id
   AND a.activity_date > u.signup_date
   AND a.activity_date <= u.signup_date + INTERVAL '7 days'

GROUP BY u.user_id;
```

---

# 19. Find Days Since Signup

This is another very important retention technique.

Instead of checking only Day-1 or Day-7, calculate:

```text
activity_date - signup_date
```

Example for User 1:

| signup_date | activity_date | days_since_signup |
| ----------- | ------------- | ----------------: |
| Jan 01      | Jan 01        |                 0 |
| Jan 01      | Jan 02        |                 1 |
| Jan 01      | Jan 05        |                 4 |

SQL:

```sql
SELECT
    u.user_id,
    u.signup_date,
    a.activity_date,
    a.activity_date - u.signup_date AS days_since_signup

FROM users u

JOIN user_activity a
    ON u.user_id = a.user_id;
```

---

# 20. Expected Output

| user_id | signup_date | activity_date | days_since_signup |
| ------: | ----------- | ------------- | ----------------: |
|       1 | Jan 01      | Jan 01        |                 0 |
|       1 | Jan 01      | Jan 02        |                 1 |
|       1 | Jan 01      | Jan 05        |                 4 |
|       2 | Jan 01      | Jan 01        |                 0 |
|       2 | Jan 01      | Jan 03        |                 2 |
|       3 | Jan 01      | Jan 01        |                 0 |
|       3 | Jan 01      | Jan 02        |                 1 |
|       4 | Jan 01      | Jan 01        |                 0 |
|       5 | Jan 01      | Jan 01        |                 0 |
|       5 | Jan 01      | Jan 02        |                 1 |

Now we can ask:

```text
How many users were active on Day 0?
How many on Day 1?
How many on Day 2?
How many on Day 4?
```

# 21. Count Retained Users by Day

```sql
SELECT
    a.activity_date - u.signup_date AS days_since_signup,
    COUNT(DISTINCT u.user_id) AS retained_users

FROM users u

JOIN user_activity a
    ON u.user_id = a.user_id

GROUP BY
    a.activity_date - u.signup_date

ORDER BY
    days_since_signup;
```

Possible output:

| days_since_signup | retained_users |
| ----------------: | -------------: |
|                 0 |              5 |
|                 1 |              3 |
|                 2 |              1 |
|                 4 |              1 |

Interpretation:

```text
Day 0 → 5 users
Day 1 → 3 users
Day 2 → 1 user
Day 4 → 1 user
```

---

# 22. Why COUNT(DISTINCT user_id)?

Suppose User 1 performed three actions on Jan 02:

| user_id | activity_date |
| ------: | ------------- |
|       1 | Jan 02        |
|       1 | Jan 02        |
|       1 | Jan 02        |

Those are three activity records.

But we want:

```text
1 retained user
```

not:

```text
3 retained users
```

Therefore:

```sql
COUNT(DISTINCT user_id)
```

is often necessary in retention analysis.

---

# 23. Retention Rate by Day

Suppose:

| Day | Retained Users |
| --: | -------------: |
|   0 |              5 |
|   1 |              3 |
|   2 |              1 |
|   4 |              1 |

Original cohort size = 5.

Therefore:

```text
Day 0
5 / 5 × 100 = 100%

Day 1
3 / 5 × 100 = 60%

Day 2
1 / 5 × 100 = 20%

Day 4
1 / 5 × 100 = 20%
```

---

# 24. General Retention Formula

```text
                 Retained Users on Day N
Retention Rate = ------------------------- × 100
                 Original Cohort Users
```

For example:

```text
Day-7 Retention
=
Users active exactly 7 days later
/
Users who originally signed up
× 100
```

# 25. A More Realistic Example

Imagine a food-delivery application.

On January 1:

```text
10,000 users signed up
```

On January 2:

```text
6,000 returned
```

On January 8:

```text
3,000 returned
```

On January 31:

```text
1,500 returned
```

Retention:

| Period | Retained Users | Retention |
| ------ | -------------: | --------: |
| Day 0  |         10,000 |      100% |
| Day 1  |          6,000 |       60% |
| Day 7  |          3,000 |       30% |
| Day 30 |          1,500 |       15% |

This tells the business:

```text
60% of new users returned the next day.
30% returned after 7 days.
15% returned after 30 days.
```

# 26. Common Mistake: Confusing Retention With Total Activity

Consider:

| user_id | activity_date |
| ------: | ------------- |
|       1 | Jan 02        |
|       1 | Jan 02        |
|       1 | Jan 02        |
|       2 | Jan 02        |

There are 4 activity records.

But retained users:

```text
User 1
User 2
```

Only 2 users.

Therefore:

```sql
COUNT(DISTINCT user_id)
```

is important.

---

# 27. Common Mistake: Using INNER JOIN for Full Retention Population

If a user did not return, we still need to count that user in the denominator.

Therefore:

```sql
FROM users u
LEFT JOIN user_activity a
```

is usually appropriate when calculating retention from the full signup population.

---

# 28. Common Mistake: Confusing These Two Questions

### Question A

> Did the user return exactly 7 days later?

Use:

```sql
activity_date = signup_date + INTERVAL '7 days'
```

### Question B

> Did the user return at any point during the first 7 days?

Use:

```sql
activity_date > signup_date
AND activity_date <= signup_date + INTERVAL '7 days'
```

These produce different results.

# 30. Core Templates

## Exact Day-N Retention

```sql
SELECT
    COUNT(DISTINCT u.user_id) AS retained_users
FROM users u
JOIN user_activity a
    ON u.user_id = a.user_id
   AND a.activity_date = u.signup_date + INTERVAL '7 days';
```

Replace `7` with `1`, `30`, etc.

---

## Days Since Signup

```sql
SELECT
    u.user_id,
    a.activity_date - u.signup_date AS days_since_signup
FROM users u
JOIN user_activity a
    ON u.user_id = a.user_id;
```

---

## Count Retained Users By Day

```sql
SELECT
    a.activity_date - u.signup_date AS day_number,
    COUNT(DISTINCT u.user_id) AS retained_users
FROM users u
JOIN user_activity a
    ON u.user_id = a.user_id
GROUP BY
    a.activity_date - u.signup_date
ORDER BY
    day_number;
```

---

## Returned Within N Days

```sql
SELECT
    u.user_id,
    COUNT(DISTINCT a.activity_date) AS active_days
FROM users u
LEFT JOIN user_activity a
    ON u.user_id = a.user_id
   AND a.activity_date > u.signup_date
   AND a.activity_date <= u.signup_date + INTERVAL '7 days'
GROUP BY
    u.user_id;
```

# 31. The Pattern to Remember

```text
User Signs Up
      ↓
Find Their Activities
      ↓
Compare Activity Date
with Signup Date
      ↓
Calculate Days Since Signup
      ↓
Count Distinct Users
      ↓
Calculate Retention %
```

The most important idea is:

> **Retention = Of the users who started at the beginning, how many came back later?**

---

# 32. Retention vs Cohort Analysis

These two concepts are related but not identical.

### Retention Analysis

Asks:

> How many users came back?

### Cohort Analysis

Asks:

> How does retention compare between different groups of users who started at different times?

For example:

```text
January signup users
February signup users
March signup users
```

and then compare their Day-1, Day-7, and Day-30 retention.

That is the natural next pattern: **Cohort Analysis**.
