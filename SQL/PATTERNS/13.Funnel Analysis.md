# SQL Pattern 13: Funnel Analysis

## 1. What Is Funnel Analysis?

**Funnel analysis** measures how users move through a sequence of steps toward a goal.

A common e-commerce funnel is:

```text
Visit Website
     ↓
View Product
     ↓
Add to Cart
     ↓
Purchase
```

The important questions are:

```text
How many users reached each step?
Where are users dropping off?
What percentage of users complete the funnel?
```

---

# 2. Simple Example

Suppose 100 users visit a website.

```text
100 → Visit
 80 → View Product
 50 → Add to Cart
 30 → Purchase
```

The funnel is:

```text
Visit
 100 users
    ↓
View Product
  80 users
    ↓
Add to Cart
  50 users
    ↓
Purchase
  30 users
```

So:

```text
Visit → View Product
80 / 100 = 80%

View Product → Add to Cart
50 / 80 = 62.5%

Add to Cart → Purchase
30 / 50 = 60%

Overall conversion:
30 / 100 = 30%
```

---

# 3. Problem Statement

Given a table of user events, calculate:

1. Number of users who reached each funnel step.
2. Conversion rate between steps.
3. Overall funnel conversion rate.
4. Drop-off between steps.

We will use this funnel:

```text
Step 1 → Visit
Step 2 → Product View
Step 3 → Add to Cart
Step 4 → Purchase
```

# 7. The Most Important Rule

A user should normally count **once per funnel step**, even if they performed the event multiple times.

For example:

```text
User 1
Visit
Product View
Product View
Product View
Add to Cart
```

User 1 is still:

```text
Product View = 1 user
```

not:

```text
Product View = 3 users
```

Therefore funnel analysis usually uses:

```sql
COUNT(DISTINCT user_id)
```

---

# 8. Template 1 — Basic Funnel Counts

## Problem

Count unique users for every funnel step.

```sql id="1im8fs"
SELECT
    event_type,
    COUNT(DISTINCT user_id) AS users
FROM events
WHERE event_type IN (
    'visit',
    'product_view',
    'add_to_cart',
    'purchase'
)
GROUP BY event_type;
```

This gives the number of users who performed each action.

However, this query alone does **not guarantee that users completed the steps in order**.

That distinction is important.

---

# 9. Why Event Existence Alone Can Be Wrong

Suppose User 10 has:

```text
10:00 purchase
10:10 visit
```

If we only check whether the user has both events, we might incorrectly treat them as having completed:

```text
visit → purchase
```

But the order is wrong.

A proper funnel often requires:

```text
visit
   ↓
product_view
   ↓
add_to_cart
   ↓
purchase
```

in chronological order.

---

# 10. Template 2 — Find First Time of Each Event

One common approach is to find the first occurrence of every funnel event for each user.

```sql id="k1l6t0"
SELECT
    user_id,

    MIN(event_time) FILTER (
        WHERE event_type = 'visit'
    ) AS visit_time,

    MIN(event_time) FILTER (
        WHERE event_type = 'product_view'
    ) AS product_view_time,

    MIN(event_time) FILTER (
        WHERE event_type = 'add_to_cart'
    ) AS add_to_cart_time,

    MIN(event_time) FILTER (
        WHERE event_type = 'purchase'
    ) AS purchase_time

FROM events
GROUP BY user_id;
```

# 12. Template 3 — Determine Funnel Completion

For each user, check whether each next step occurred after the previous step.

```sql id="yvj2ck"
WITH user_steps AS (
    SELECT
        user_id,

        MIN(event_time) FILTER (
            WHERE event_type = 'visit'
        ) AS visit_time,

        MIN(event_time) FILTER (
            WHERE event_type = 'product_view'
        ) AS product_view_time,

        MIN(event_time) FILTER (
            WHERE event_type = 'add_to_cart'
        ) AS add_to_cart_time,

        MIN(event_time) FILTER (
            WHERE event_type = 'purchase'
        ) AS purchase_time

    FROM events
    GROUP BY user_id
)

SELECT
    user_id,

    CASE
        WHEN visit_time IS NOT NULL
        THEN 1 ELSE 0
    END AS completed_visit,

    CASE
        WHEN product_view_time > visit_time
        THEN 1 ELSE 0
    END AS completed_product_view,

    CASE
        WHEN add_to_cart_time > product_view_time
        THEN 1 ELSE 0
    END AS completed_add_to_cart,

    CASE
        WHEN purchase_time > add_to_cart_time
        THEN 1 ELSE 0
    END AS completed_purchase

FROM user_steps;
```

This creates user-level funnel flags.

|       1 |     1 |            1 |           1 |        1 |
|       2 |     1 |            1 |           1 |        0 |
|       3 |     1 |            1 |           0 |        0 |
|       4 |     1 |            0 |           0 |        0 |
|       5 |     1 |            1 |           1 |        1 |

Now the funnel is much easier to understand.

# 14. Template 4 — Count Users at Each Funnel Step

Instead of counting every event, count users who successfully reached each step.

```sql id="1g6wcg"
WITH user_steps AS (
    SELECT
        user_id,

        MIN(event_time) FILTER (
            WHERE event_type = 'visit'
        ) AS visit_time,

        MIN(event_time) FILTER (
            WHERE event_type = 'product_view'
        ) AS product_view_time,

        MIN(event_time) FILTER (
            WHERE event_type = 'add_to_cart'
        ) AS add_to_cart_time,

        MIN(event_time) FILTER (
            WHERE event_type = 'purchase'
        ) AS purchase_time

    FROM events
    GROUP BY user_id
)

SELECT
    COUNT(*) FILTER (
        WHERE visit_time IS NOT NULL
    ) AS visit_users,

    COUNT(*) FILTER (
        WHERE product_view_time > visit_time
    ) AS product_view_users,

    COUNT(*) FILTER (
        WHERE add_to_cart_time > product_view_time
    ) AS cart_users,

    COUNT(*) FILTER (
        WHERE purchase_time > add_to_cart_time
    ) AS purchase_users

FROM user_steps;
```

Expected:

| visit_users | product_view_users | cart_users | purchase_users |
| ----------: | -----------------: | ---------: | -------------: |
|           5 |                  4 |          3 |              2 |

---

# 15. Conversion Rate

There are two common conversion measurements.

## Step-to-Step Conversion

This asks:

> Of the users who reached the previous step, how many reached the next step?

For our example:

```text
Visit → Product View
4 / 5 = 80%

Product View → Add to Cart
3 / 4 = 75%

Add to Cart → Purchase
2 / 3 = 66.67%
```

---

# 16. Overall Conversion

This asks:

> Of everyone who entered the funnel, how many completed the final step?

Formula:

```text
Purchase Users
/
Visit Users
× 100
```

For our example:

```text
2 / 5 × 100
=
40%
```

---

# 17. Template 5 — Calculate Conversion Rates

Once you have the funnel counts:

```sql id="h7em8o"
WITH funnel AS (
    SELECT
        5 AS visit_users,
        4 AS product_view_users,
        3 AS cart_users,
        2 AS purchase_users
)

SELECT
    visit_users,
    product_view_users,
    cart_users,
    purchase_users,

    product_view_users * 100.0
        / visit_users AS visit_to_product_rate,

    cart_users * 100.0
        / product_view_users AS product_to_cart_rate,

    purchase_users * 100.0
        / cart_users AS cart_to_purchase_rate,

    purchase_users * 100.0
        / visit_users AS overall_conversion_rate

FROM funnel;
```

For learning purposes, the values are explicit here. In a production query, these counts would come from the previous CTE rather than hard-coded numbers.

---

# 18. Expected Output

| visit_to_product_rate | product_to_cart_rate | cart_to_purchase_rate | overall_conversion_rate |
| --------------------: | -------------------: | --------------------: | ----------------------: |
|                80.00% |               75.00% |                66.67% |                  40.00% |

# 19. Drop-Off Analysis

A funnel is also used to identify where the biggest drop happens.

Our counts:

```text
Visit           5
 ↓ -1
Product View    4
 ↓ -1
Add to Cart     3
 ↓ -1
Purchase        2
```

In this small example, one user drops at every step.

Formula:

```text
Drop-off
=
Previous Step Users - Current Step Users
```

---

# 20. Drop-Off Percentage

For:

```text
Visit → Product View
```

we have:

```text
5 - 4 = 1 user dropped
```

Drop-off rate:

```text
1 / 5 × 100 = 20%
```

For:

```text
Product View → Add to Cart
```

```text
4 - 3 = 1
```

Drop-off:

```text
1 / 4 × 100 = 25%
```

For:

```text
Add to Cart → Purchase
```

```text
3 - 2 = 1
```

Drop-off:

```text
1 / 3 × 100 = 33.33%
```

# 21. Important Funnel Concept: Sequential vs Non-Sequential

There are two common interpretations.

## Non-Sequential Funnel

Question:

> Did the user perform each event at any point?

Example:

```text
Visit
...
Purchase
...
Product View
```

The user has all three events, so a simple event-existence query may count them.

## Sequential Funnel

Question:

> Did the user perform the steps in the required order?

Example:

```text
Visit
 ↓
Product View
 ↓
Purchase
```

This requires timestamps and ordering.

For interview questions, carefully read the wording.

If the problem says:

> "performed A before B before C"

you must enforce event order.

---

# 22. Time-Bounded Funnel

Sometimes the business requires the funnel to complete within a specific period.

Example:

> User must purchase within 24 hours of visiting.

Then:

```sql id="xgv9c1"
purchase_time <= visit_time + INTERVAL '24 hours'
```

Example:

```text
Visit     → 10:00
Purchase  → 11:30

1.5 hours
→ qualifies
```

But:

```text
Visit     → 10:00
Purchase  → next day 15:00

29 hours
→ does not qualify
```

---

# 23. Common Interview Variation

## Problem

Find users who completed:

```text
Login
 ↓
Search
 ↓
Purchase
```

within 7 days.

The logic becomes:

```text
1. Find first login.
2. Find search after login.
3. Find purchase after search.
4. Check purchase <= login + 7 days.
```

The exact SQL structure depends on the event model.

---

# 24. Another Common Approach: Conditional Aggregation

For simple funnels, conditional aggregation is very useful.

```sql id="ef6z5s"
SELECT
    COUNT(DISTINCT user_id) FILTER (
        WHERE event_type = 'visit'
    ) AS visits,

    COUNT(DISTINCT user_id) FILTER (
        WHERE event_type = 'product_view'
    ) AS product_views,

    COUNT(DISTINCT user_id) FILTER (
        WHERE event_type = 'add_to_cart'
    ) AS add_to_cart,

    COUNT(DISTINCT user_id) FILTER (
        WHERE event_type = 'purchase'
    ) AS purchases

FROM events;
```

This is concise, but remember:

> It doesn't by itself guarantee event ordering.

# 25. Real-World Example

Consider an e-commerce application.

Suppose:

```text
100,000 users visit
        ↓
70,000 view a product
        ↓
30,000 add to cart
        ↓
12,000 purchase
```

Funnel:

```text
Visit          100,000
                  ↓
Product View     70,000
                  ↓
Add to Cart      30,000
                  ↓
Purchase         12,000
```

Conversion:

```text
Visit → Product View
70,000 / 100,000 = 70%

Product View → Cart
30,000 / 70,000 = 42.86%

Cart → Purchase
12,000 / 30,000 = 40%

Overall
12,000 / 100,000 = 12%
```

This immediately tells the business that the largest percentage drop happens between:

```text
Product View
     ↓
Add to Cart
```

# 26. Common Mistakes

## Mistake 1 — Counting Rows Instead of Users

Wrong:

```sql
COUNT(*)
```

A user can perform the same action multiple times.

Usually use:

```sql
COUNT(DISTINCT user_id)
```

---

## Mistake 2 — Ignoring Event Order

This:

```text
Purchase
Visit
```

shouldn't automatically count as:

```text
Visit → Purchase
```

when the funnel requires sequence.

Use timestamps.

---

## Mistake 3 — Using the Wrong Denominator

For step conversion:

```text
Current Step Users
/
Previous Step Users
```

For overall conversion:

```text
Final Step Users
/
First Step Users
```

These are different metrics.

---

## Mistake 4 — Ignoring Time Limits

Some funnels require:

```text
within 24 hours
within 7 days
within 30 days
```

You must include the time condition.

    ↓

       ↓

The key idea is:

> **Funnel analysis tells you how many users successfully move from one business step to the next, and where they stop.**

# 30. Retention vs Cohort vs Funnel

These are easy to confuse.

### Retention

```text
Did users come back?
```

### Cohort

```text
Do different groups of users
retain differently over time?
```

### Funnel

```text
How many users move through
a sequence of steps?
```

A single product analytics system may use all three:

```text
Signup
   ↓
Funnel → Did user activate and purchase?
   ↓
Retention → Did user come back?
   ↓
Cohort → Did January users retain better than February users?
```
