# SQL Pattern 15: Time Series Analysis

## 1. What Is Time Series Analysis?

**Time series analysis** means analyzing data that is recorded over time and looking for patterns such as:

```text
Growth
Decline
Seasonality
Running totals
Moving averages
Rolling metrics
Period-over-period changes
```

Examples:

- Daily sales
- Monthly revenue
- Daily website users
- Hourly CPU usage
- Monthly orders
- Stock prices

The key difference from basic trend analysis is that **time series analysis combines multiple time-based SQL patterns together**.

---

# 2. Simple Example

Suppose we have daily sales:

| sale_date | sales |
|------------|------:|
| 2024-01-01 | 100 |
| 2024-01-02 | 150 |
| 2024-01-03 | 120 |
| 2024-01-04 | 180 |
| 2024-01-05 | 200 |

We may want to know:

```text
What were today's sales?
What were yesterday's sales?
How much did sales change?
What is the running total?
What is the 3-day moving average?
What is the 3-day rolling maximum?
```

This is time series analysis.

---

# 3. Problem Statement

Given daily sales data, calculate:

1. Daily sales.
2. Previous day's sales.
3. Change from the previous day.
4. Percentage growth.
5. Running total.
6. 3-day moving average.
7. 3-day rolling maximum.

# 7. Step 1 — Previous Day's Sales

Use `LAG()`.

```sql
SELECT
    sale_date,
    sales,

    LAG(sales) OVER (
        ORDER BY sale_date
    ) AS previous_sales

FROM daily_sales;
```

Output:

| sale_date | sales | previous_sales |
|------------|------:|---------------:|
| Jan 01 | 100 | NULL |
| Jan 02 | 150 | 100 |
| Jan 03 | 120 | 150 |
| Jan 04 | 180 | 120 |
| Jan 05 | 200 | 180 |

---

# 8. Step 2 — Daily Change

Formula:

```text
Current Sales - Previous Sales
```

SQL:

```sql
SELECT
    sale_date,
    sales,

    sales - LAG(sales) OVER (
        ORDER BY sale_date
    ) AS daily_change

FROM daily_sales;
```

Output:

| sale_date | sales | daily_change |
|------------|------:|-------------:|
| Jan 01 | 100 | NULL |
| Jan 02 | 150 | 50 |
| Jan 03 | 120 | -30 |
| Jan 04 | 180 | 60 |
| Jan 05 | 200 | 20 |

---

# 9. Step 3 — Daily Growth Percentage

Formula:

```text
(Current - Previous)
-------------------- × 100
     Previous
```

SQL:

```sql
WITH data AS (
    SELECT
        sale_date,
        sales,
        LAG(sales) OVER (
            ORDER BY sale_date
        ) AS previous_sales
    FROM daily_sales
)

SELECT
    sale_date,
    sales,
    previous_sales,

    ROUND(
        (sales - previous_sales) * 100.0
        / NULLIF(previous_sales, 0),
        2
    ) AS growth_pct

FROM data;
```

Output:

| sale_date | sales | growth_pct |
|------------|------:|-----------:|
| Jan 01 | 100 | NULL |
| Jan 02 | 150 | 50.00 |
| Jan 03 | 120 | -20.00 |
| Jan 04 | 180 | 50.00 |
| Jan 05 | 200 | 11.11 |

---

# 10. Step 4 — Running Total

Running total answers:

> How much sales have we accumulated so far?

```sql
SELECT
    sale_date,
    sales,

    SUM(sales) OVER (
        ORDER BY sale_date
    ) AS running_total

FROM daily_sales;
```

Output:

| sale_date | sales | running_total |
|------------|------:|--------------:|
| Jan 01 | 100 | 100 |
| Jan 02 | 150 | 250 |
| Jan 03 | 120 | 370 |
| Jan 04 | 180 | 550 |
| Jan 05 | 200 | 750 |

---

# 11. Step 5 — 3-Day Moving Average

A moving average uses a sliding window.

```sql
AVG(sales) OVER (
    ORDER BY sale_date
    ROWS BETWEEN 2 PRECEDING
    AND CURRENT ROW
)
```

Complete query:

```sql
SELECT
    sale_date,
    sales,

    ROUND(
        AVG(sales) OVER (
            ORDER BY sale_date
            ROWS BETWEEN 2 PRECEDING
            AND CURRENT ROW
        ),
        2
    ) AS moving_avg_3d

FROM daily_sales;
```

---

# 12. Understand the 3-Day Window

For Jan 5:

```text
Jan 03 = 120
Jan 04 = 180
Jan 05 = 200
```

Average:

```text
(120 + 180 + 200) / 3
= 166.67
```

Therefore:

| sale_date | moving_avg_3d |
|------------|--------------:|
| Jan 01 | 100.00 |
| Jan 02 | 125.00 |
| Jan 03 | 123.33 |
| Jan 04 | 150.00 |
| Jan 05 | 166.67 |

---

# 13. Step 6 — Rolling Maximum

Find the highest sales value in the current and previous 2 rows.

```sql
SELECT
    sale_date,
    sales,

    MAX(sales) OVER (
        ORDER BY sale_date
        ROWS BETWEEN 2 PRECEDING
        AND CURRENT ROW
    ) AS rolling_max_3d

FROM daily_sales;
```

Output:

| sale_date | rolling_max_3d |
|------------|---------------:|
| Jan 01 | 100 |
| Jan 02 | 150 |
| Jan 03 | 150 |
| Jan 04 | 180 |
| Jan 05 | 200 |

---

# 14. Complete Time Series Query

Now combine everything.

```sql
WITH base AS (
    SELECT
        sale_date,
        sales,

        LAG(sales) OVER (
            ORDER BY sale_date
        ) AS previous_sales

    FROM daily_sales
)

SELECT
    sale_date,
    sales,
    previous_sales,

    sales - previous_sales AS daily_change,

    ROUND(
        (sales - previous_sales) * 100.0
        / NULLIF(previous_sales, 0),
        2
    ) AS growth_pct,

    SUM(sales) OVER (
        ORDER BY sale_date
    ) AS running_total,

    ROUND(
        AVG(sales) OVER (
            ORDER BY sale_date
            ROWS BETWEEN 2 PRECEDING
            AND CURRENT ROW
        ),
        2
    ) AS moving_avg_3d,

    MAX(sales) OVER (
        ORDER BY sale_date
        ROWS BETWEEN 2 PRECEDING
        AND CURRENT ROW
    ) AS rolling_max_3d

FROM base
ORDER BY sale_date;
```

# 16. Template 1 — Daily → Weekly Aggregation

Time series data is often stored at a lower granularity but analyzed at a higher granularity.

For example:

```text
Daily data
↓
Weekly revenue
```

Use:

```sql
SELECT
    DATE_TRUNC('week', sale_date) AS week,
    SUM(sales) AS weekly_sales
FROM daily_sales
GROUP BY
    DATE_TRUNC('week', sale_date)
ORDER BY
    week;
```

---

# 17. Template 2 — Daily → Monthly Aggregation

```sql
SELECT
    DATE_TRUNC('month', sale_date) AS month,
    SUM(sales) AS monthly_sales
FROM daily_sales
GROUP BY
    DATE_TRUNC('month', sale_date)
ORDER BY
    month;
```

This is one of the most common Data Engineering analytics patterns.

---

# 18. Template 3 — Monthly Revenue + MoM Growth

```sql
WITH monthly AS (
    SELECT
        DATE_TRUNC('month', sale_date) AS month,
        SUM(sales) AS revenue
    FROM daily_sales
    GROUP BY
        DATE_TRUNC('month', sale_date)
),

data AS (
    SELECT
        month,
        revenue,
        LAG(revenue) OVER (
            ORDER BY month
        ) AS previous_revenue
    FROM monthly
)

SELECT
    month,
    revenue,
    previous_revenue,

    ROUND(
        (revenue - previous_revenue) * 100.0
        / NULLIF(previous_revenue, 0),
        2
    ) AS mom_growth_pct

FROM data
ORDER BY month;
```

---

# 19. Template 4 — Year-over-Year Comparison

Suppose monthly data contains several years.

You may want:

```text
January 2025
vs
January 2024
```

If every month exists:

```sql
LAG(revenue, 12) OVER (
    ORDER BY month
)
```

Example:

```sql
SELECT
    month,
    revenue,

    LAG(revenue, 12) OVER (
        ORDER BY month
    ) AS same_month_last_year

FROM monthly_revenue;
```

Then:

```text
YoY Growth
=
(Current - Last Year)
/
Last Year
× 100
```

# 20. Template 5 — Time Series Per Customer

Suppose every customer has monthly revenue.

```text
Customer 1
Jan → Feb → Mar

Customer 2
Jan → Feb → Mar
```

Use:

```sql
LAG(revenue) OVER (
    PARTITION BY customer_id
    ORDER BY month
)
```

Example:

```sql
SELECT
    customer_id,
    month,
    revenue,

    LAG(revenue) OVER (
        PARTITION BY customer_id
        ORDER BY month
    ) AS previous_revenue

FROM customer_monthly_revenue;
```

# 21. Template 6 — Running Total Per Customer

```sql
SELECT
    customer_id,
    month,
    revenue,

    SUM(revenue) OVER (
        PARTITION BY customer_id
        ORDER BY month
    ) AS cumulative_revenue

```

Each customer's running total is calculated independently.

# 22. Template 7 — Rolling 7-Day Sales

```sql
SELECT
    sale_date,
    sales,

    SUM(sales) OVER (
        ORDER BY sale_date
        ROWS BETWEEN 6 PRECEDING
        AND CURRENT ROW
    ) AS rolling_7_day_sales

FROM daily_sales;
```

This means:

```text
Current day
+
Previous 6 rows
=
7-row window
```

Important: this is a **7-row** window, not necessarily 7 calendar days if dates are missing.

# 23. Missing Dates — Important Time Series Issue

Consider:

| sale_date | sales |
|------------|------:|
| Jan 01 | 100 |
| Jan 02 | 150 |
| Jan 05 | 200 |

There are no records for:

```text
Jan 03
Jan 04
```

This matters.

If you use:

```sql
ROWS BETWEEN 2 PRECEDING
AND CURRENT ROW
```

the database looks at **rows**, not calendar dates.

It sees:

```text
Jan 01
Jan 02
Jan 05
```

and considers these three rows adjacent.

So:

```text
ROWS ≠ Calendar Days
```

This distinction is extremely important in real Data Engineering work.

---

# 24. ROWS vs RANGE in Time Series

## ROWS

Means:

> Previous N rows.

```sql
ROWS BETWEEN 6 PRECEDING AND CURRENT ROW
```

## RANGE

Works based on the value of the ordering column and can represent a value-based interval.

For timestamp/date-based analytics, the exact syntax and behavior depend on the database.

The important interview concept is:

```text
ROWS
→ physical rows

RANGE
→ value-based window
```

# 27. Common Mistakes

## Mistake 1 — Not Ordering by Time

Wrong:

```sql
LAG(sales) OVER ()
```

Correct:

```sql
LAG(sales) OVER (
    ORDER BY sale_date
)
```

---

## Mistake 2 — Using `ROWS` Without Understanding Missing Dates

This:

```sql
ROWS BETWEEN 6 PRECEDING AND CURRENT ROW
```

means 7 rows, not necessarily 7 calendar days.

---

## Mistake 3 — Using Daily Data Without Aggregating First

If you need monthly revenue, don't calculate the monthly trend directly from raw event rows.

First:

```text
Daily Events
↓
Monthly Aggregation
↓
Monthly Trend
```

---

## Mistake 4 — Forgetting Duplicate Events

For user metrics, multiple events from one user may need:

```sql
COUNT(DISTINCT user_id)
```

rather than:

```sql
COUNT(*)
```

### Previous Period

```sql
LAG(value) OVER (
    ORDER BY date
)
```


```sql
SUM(value) OVER (
    ORDER BY date

```

### Moving Average

```sql
AVG(value) OVER (
    ORDER BY date

    AND CURRENT ROW

```

```sql
SUM(value) OVER (
    ORDER BY date

    AND CURRENT ROW
```

```sql
DATE_TRUNC('month', date)
```

```text
(Current - Previous)
/

```

```sql
LAG(value, 12) OVER (
```

# 30. Core Mental Model

Think about Time Series Analysis as a combination of the patterns you already learned:

```text
                     TIME SERIES
                         |
          +--------------+--------------+
          |              |              |
        LAG()         SUM()           AVG()
          |              |              |
      Change         Running        Moving
      /Trend         Total          Average
          |              |              |
          +--------------+--------------+
                         |
                   Rolling Metrics
```

You are not learning a completely new family of functions here.

You are combining:

```text
Running Total
Moving Average
Rolling Window
Change Detection
Trend Analysis
Date Functions
```

into one time-based analysis.

# 31. Interview Pattern

When given a problem like:

> "Calculate the 7-day rolling sales, daily growth, cumulative sales, and month-over-month revenue growth."

Break it into:

```text
1. Group by time period
2. LAG() for previous value
3. Calculate change
4. Calculate percentage growth
5. SUM() OVER() for cumulative value
6. AVG() / SUM() OVER() for rolling metrics
```
