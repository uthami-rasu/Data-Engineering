# SQL Pattern 5: Change Detection (LAG & LEAD)

## Purpose

Compare a row with its previous or next row.

This pattern is used to answer questions like:

- Did revenue increase or decrease?
- Did salary change?
- Did stock price go up or down?
- What is the growth percentage?
- What changed compared to the previous record?

---

# Core Functions

## LAG()

Returns a value from the previous row.

```sql
LAG(column_name)
```

---

## LEAD()

Returns a value from the next row.

```sql
LEAD(column_name)
```

---

# Input Data

## Monthly Revenue

| month | revenue |
| ----- | ------: |
| Jan   |    1000 |
| Feb   |    1200 |
| Mar   |     900 |
| Apr   |    1500 |

# Template 1: Previous Row Comparison

## Problem Statement

Show current revenue and previous month's revenue.

### SQL

```sql
SELECT
    month,
    revenue,
    LAG(revenue) OVER(
        ORDER BY month
    ) AS prev_revenue
FROM sales;
```

### Output

| month | revenue | prev_revenue |
| ----- | ------: | -----------: |
| Jan   |    1000 |         NULL |
| Feb   |    1200 |         1000 |
| Mar   |     900 |         1200 |
| Apr   |    1500 |          900 |

### Use Cases

- Previous salary
- Previous stock price
- Previous month's sales

# Template 3: Absolute Change

## Problem Statement

Find the difference between current and previous revenue.

### Formula

```text
Current Revenue - Previous Revenue
```

### SQL

```sql
SELECT
    month,
    revenue,
    revenue -
    LAG(revenue) OVER(
        ORDER BY month
    ) AS revenue_change
FROM sales;
```

### Output

| month | revenue_change |
| ----- | -------------: |
| Jan   |           NULL |
| Feb   |            200 |
| Mar   |           -300 |
| Apr   |            600 |

### Interpretation

```text
Positive = Increase
Negative = Decrease
Zero     = No Change
```

# Template 4: Percentage Change

## Problem Statement

Calculate month-over-month growth percentage.

### Formula

```text
(Current - Previous)
/
Previous * 100
```

### SQL

```sql
SELECT
    month,
    revenue,
    ROUND(
        (
            revenue -
            LAG(revenue) OVER(
                ORDER BY month
            )
        ) * 100.0
        /
        LAG(revenue) OVER(
            ORDER BY month
        ),
        2
    ) AS growth_pct
FROM sales;
```

### Output

| month | growth_pct |
| ----- | ---------: |
| Jan   |       NULL |
| Feb   |      20.00 |
| Mar   |     -25.00 |
| Apr   |      66.67 |

### Use Cases

- Revenue growth
- User growth
- Profit growth
- Sales growth

# Template 5: Trend Detection

## Problem Statement

Identify whether revenue increased, decreased, or remained the same.

### SQL

```sql
SELECT
    month,
    revenue,
    CASE
        WHEN revenue >
             LAG(revenue) OVER(
                 ORDER BY month
             )
        THEN 'UP'

        WHEN revenue <
             LAG(revenue) OVER(
                 ORDER BY month
             )
        THEN 'DOWN'

        ELSE 'SAME'
    END AS trend
FROM sales;
```

### Output

| month | trend |
| ----- | ----- |
| Jan   | SAME  |
| Feb   | UP    |
| Mar   | DOWN  |
| Apr   | UP    |

### Use Cases

- Revenue trend
- Stock trend
- Traffic trend
- KPI monitoring

# Template 6: First and Last Record Detection

## Problem Statement

Find first or last event for a user.

### First Event

```sql
SELECT *
FROM (
    SELECT
        *,
        ROW_NUMBER() OVER(
            PARTITION BY user_id
            ORDER BY event_date
        ) AS rn
    FROM events
) t
WHERE rn = 1;
```

### Last Event

```sql
SELECT *
FROM (
    SELECT
        *,
        ROW_NUMBER() OVER(
            PARTITION BY user_id
            ORDER BY event_date DESC
        ) AS rn
    FROM events
) t
WHERE rn = 1;
```

### Use Cases

- First purchase
- Latest order
- First login
- Last activity

# Template 7: Detect Value Changes

## Problem Statement

Identify when a value changes compared to the previous row.

### Input

| emp_id | salary |
| ------ | -----: |
| 1      |   5000 |
| 1      |   5000 |
| 1      |   6000 |
| 1      |   6000 |
| 1      |   7000 |

### SQL

```sql
SELECT
    emp_id,
    salary,
    CASE
        WHEN salary <>
             LAG(salary) OVER(
                 PARTITION BY emp_id
                 ORDER BY emp_id
             )
        THEN 'CHANGED'
        ELSE 'NO CHANGE'
    END AS status
FROM employee_salary;
```

### Output

| salary | status    |
| ------ | --------- |
| 5000   | NO CHANGE |
| 5000   | NO CHANGE |
| 6000   | CHANGED   |
| 6000   | NO CHANGE |
| 7000   | CHANGED   |

### Use Cases

- Salary revisions
- Price changes
- Status changes
- Address changes
