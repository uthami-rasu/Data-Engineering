# SQL Pattern 12: Cohort Analysis

## 1. What Is Cohort Analysis?

**Cohort analysis** groups users based on a common starting point and then tracks how those groups behave over time.

The most common starting point is:

```text
User signup month
```

For example:

```text
January signups  → January Cohort
February signups → February Cohort
March signups    → March Cohort
```

Then we compare how each cohort behaves after signup.

For example:

```text
January Cohort
    ↓
Month 0 → 100%
Month 1 → 60%
Month 2 → 40%

February Cohort
    ↓
Month 0 → 100%
Month 1 → 70%
Month 2 → 45%
```

This helps answer:

> Are newer groups of users retaining better or worse than older groups?

---

# 2. Cohort Analysis vs Retention Analysis

These concepts are closely related.

## Retention Analysis

Asks:

> How many users came back after signup?

Example:

```text
Day 1 retention = 60%
Day 7 retention = 30%
Day 30 retention = 15%
```

## Cohort Analysis

Adds another dimension:

> How does retention differ between users who joined at different times?

Example:

```text
January Cohort → 60% Day-1 retention
February Cohort → 70% Day-1 retention
March Cohort → 75% Day-1 retention
```

So:

```text
Retention = Measure returning users

Cohort = Group users by when they started
```

---

# 3. Problem Statement

Given users and their activities:

1. Determine each user's cohort month.
2. Determine which month each user was active.
3. Calculate the number of months since signup.
4. Count retained users for each cohort and month.
5. Calculate the retention percentage.

# 5. Step 1 — Identify the Cohort

A user's cohort is the month in which they signed up.

For example:

```text
User 1 → Jan 10 → January Cohort
User 2 → Jan 20 → January Cohort
User 3 → Jan 25 → January Cohort

User 4 → Feb 05 → February Cohort
User 5 → Feb 15 → February Cohort

User 6 → Mar 05 → March Cohort
```

Using PostgreSQL:

```sql
DATE_TRUNC('month', signup_date)
```

---

# 6. Create the Cohort

```sql
SELECT
    user_id,
    signup_date,
    DATE_TRUNC('month', signup_date) AS cohort_month
FROM users;
```

## Output

| user_id | signup_date | cohort_month |
| ------: | ----------- | ------------ |
|       1 | Jan 10      | Jan 01       |
|       2 | Jan 20      | Jan 01       |
|       3 | Jan 25      | Jan 01       |
|       4 | Feb 05      | Feb 01       |
|       5 | Feb 15      | Feb 01       |
|       6 | Mar 05      | Mar 01       |

The exact displayed day is usually the first day of the month because of `DATE_TRUNC`.

---

# 7. Step 2 — Find the Activity Month

We also need to convert every activity date to its month.

```sql
DATE_TRUNC('month', activity_date)
```

For example:

```text
2024-01-10 → 2024-01-01
2024-02-05 → 2024-02-01
2024-03-10 → 2024-03-01
```

---

# 8. Step 3 — Calculate Months Since Signup

This is the most important part of cohort analysis.

For User 1:

```text
Signup       = January
Activity     = January
Months later = 0
```

For February:

```text
Signup       = January
Activity     = February
Months later = 1
```

For March:

```text
Signup       = January
Activity     = March
Months later = 2
```

So:

```text
Month 0 = Signup Month
Month 1 = First Month After Signup
Month 2 = Second Month After Signup
```

---

# 9. PostgreSQL Calculation

Use:

```sql
EXTRACT(
    YEAR FROM AGE(activity_month, cohort_month)
) * 12
+
EXTRACT(
    MONTH FROM AGE(activity_month, cohort_month)
)
```

This converts the difference into the number of months.

Example:

```text
January → January = 0
January → February = 1
January → March = 2
```

---

# 10. Build User Cohort Data

```sql
WITH user_cohorts AS (
    SELECT
        user_id,
        DATE_TRUNC('month', signup_date) AS cohort_month
    FROM users
)
SELECT
    uc.user_id,
    uc.cohort_month,
    DATE_TRUNC('month', a.activity_date) AS activity_month
FROM user_cohorts uc
JOIN user_activity a
    ON uc.user_id = a.user_id;
```

# 12. Step 4 — Calculate Month Number

```sql
WITH user_cohorts AS (
    SELECT
        user_id,
        DATE_TRUNC('month', signup_date) AS cohort_month
    FROM users
),

activity AS (
    SELECT
        uc.user_id,
        uc.cohort_month,
        DATE_TRUNC('month', a.activity_date) AS activity_month
    FROM user_cohorts uc
    JOIN user_activity a
        ON uc.user_id = a.user_id
)

SELECT
    user_id,
    cohort_month,
    activity_month,

    (
        EXTRACT(
            YEAR FROM AGE(activity_month, cohort_month)
        ) * 12
        +
        EXTRACT(
            MONTH FROM AGE(activity_month, cohort_month)
        )
    )::INT AS month_number

FROM activity;
```

# 14. What Does Month Number Mean?

This is very important.

For the January cohort:

```text
Month 0
↓
January

Month 1
↓
February

Month 2
↓
March
```

For the February cohort:

```text
Month 0
↓
February

Month 1
↓
March
```

So every cohort has its own starting point.

That is the whole idea of cohort analysis.

# 15. Step 5 — Count Users

Now calculate how many unique users from each cohort were active in each month.

```sql
WITH user_cohorts AS (
    SELECT
        user_id,
        DATE_TRUNC('month', signup_date) AS cohort_month
    FROM users
),

activity AS (
    SELECT DISTINCT
        uc.user_id,
        uc.cohort_month,
        DATE_TRUNC('month', a.activity_date) AS activity_month
    FROM user_cohorts uc
    JOIN user_activity a
        ON uc.user_id = a.user_id
),

cohort_activity AS (
    SELECT
        cohort_month,
        activity_month,

        (
            EXTRACT(
                YEAR FROM AGE(activity_month, cohort_month)
            ) * 12
            +
            EXTRACT(
                MONTH FROM AGE(activity_month, cohort_month)
            )
        )::INT AS month_number,

        user_id

    FROM activity
)

SELECT
    cohort_month,
    month_number,
    COUNT(DISTINCT user_id) AS active_users
FROM cohort_activity
GROUP BY
    cohort_month,
    month_number
ORDER BY
    cohort_month,
    month_number;
```

# 18. Calculate Retention Percentage

The formula is:

```text
Retention %
=
Active Users in Month N
/
Users in Cohort
× 100
```

For January:

```text
Month 0:
3 / 3 × 100 = 100%

Month 1:
3 / 3 × 100 = 100%

Month 2:
1 / 3 × 100 = 33.33%
```

---

# 19. Final Cohort Retention Table

Expected result:

| Cohort | Month 0 | Month 1 | Month 2 |
| ------ | ------: | ------: | ------: |
| Jan    |    100% |    100% |  33.33% |
| Feb    |    100% |     50% |       — |
| Mar    |    100% |       — |       — |

This is the classic **cohort retention table**.

# 20. Complete Cohort Retention Query

```sql
WITH user_cohorts AS (
    SELECT
        user_id,
        DATE_TRUNC('month', signup_date) AS cohort_month
    FROM users
),

activity AS (
    SELECT DISTINCT
        uc.user_id,
        uc.cohort_month,
        DATE_TRUNC('month', a.activity_date) AS activity_month
    FROM user_cohorts uc
    JOIN user_activity a
        ON uc.user_id = a.user_id
),

cohort_activity AS (
    SELECT
        user_id,
        cohort_month,

        (
            EXTRACT(
                YEAR FROM AGE(activity_month, cohort_month)
            ) * 12
            +
            EXTRACT(
                MONTH FROM AGE(activity_month, cohort_month)
            )
        )::INT AS month_number

    FROM activity
),

active_users AS (
    SELECT
        cohort_month,
        month_number,
        COUNT(DISTINCT user_id) AS active_users
    FROM cohort_activity
    GROUP BY
        cohort_month,
        month_number
),

cohort_size AS (
    SELECT
        cohort_month,
        COUNT(*) AS cohort_users
    FROM user_cohorts
    GROUP BY cohort_month
)

SELECT
    au.cohort_month,
    au.month_number,
    au.active_users,
    cs.cohort_users,

    ROUND(
        au.active_users * 100.0 / cs.cohort_users,
        2
    ) AS retention_rate

FROM active_users au
JOIN cohort_size cs
    ON au.cohort_month = cs.cohort_month

ORDER BY
    au.cohort_month,
    au.month_number;
```

---

| ------------ | -----------: | -----------: | -----------: | -------------: |
| Jan          |            0 |            3 |            3 |         100.00 |
| Jan          |            1 |            3 |            3 |         100.00 |
| Jan          |            2 |            1 |            3 |          33.33 |
| Feb          |            0 |            2 |            2 |         100.00 |
| Feb          |            1 |            1 |            2 |          50.00 |
| Mar          |            0 |            1 |            1 |         100.00 |

# 22. Why `DISTINCT` Is Important

Suppose User 1 performs five activities in February:

```text
Feb 01
Feb 05
Feb 10
Feb 15
Feb 20
```

We don't want:

```text
User 1 = 5 users
```

We want:

```text
User 1 = 1 active user
```

Therefore:

```sql
SELECT DISTINCT
    user_id,
    cohort_month,
    activity_month
```

is useful before counting users.

And finally:

```sql
COUNT(DISTINCT user_id)
```

protects us from duplicate activity records.

# 23. Cohort Analysis in a Business Example

Imagine a SaaS application.

### January cohort

1,000 users signed up in January.

After signup:

```text
Month 0 → 1,000 users
Month 1 → 700 users
Month 2 → 550 users
Month 3 → 400 users
```

Retention:

```text
Month 0 → 100%
Month 1 → 70%
Month 2 → 55%
Month 3 → 40%
```

### February cohort

2,000 users signed up in February.

```text
Month 0 → 2,000
Month 1 → 1,600
Month 2 → 1,200
Month 3 → 1,000
```

Retention:

```text
Month 0 → 100%
Month 1 → 80%
Month 2 → 60%
Month 3 → 50%
```

Now the business can see:

```text
February users retained better than January users.
```

That is the value of cohort analysis.

# 26. Common Mistakes

## Mistake 1 — Using Activity Month as Cohort

Wrong idea:

```sql
DATE_TRUNC('month', activity_date)
```

for the cohort.

The cohort should come from the **starting event**, normally signup:

```sql
DATE_TRUNC('month', signup_date)
```

---

## Mistake 2 — Counting Activity Records

Wrong:

```sql
COUNT(*)
```

when multiple events per user exist.

Better:

```sql
COUNT(DISTINCT user_id)
```

---

## Mistake 3 — Not Calculating Relative Month

You need:

```text
Month 0
Month 1
Month 2
...
```

not just absolute calendar months.

# 30. Final Mental Model

Think of a cohort as a **group of users that started together**.

Example:

```text
January Cohort
[User 1, User 2, User 3]

February Cohort
[User 4, User 5]

March Cohort
[User 6]
```

Then ask:

```text
How many from each group are still active
after 1 month?
after 2 months?
after 3 months?
```

That is **Cohort Analysis**.

---

# 31. Retention vs Cohort — Final Difference

```text
Retention Analysis
──────────────────
"Did users come back?"

Cohort Analysis
────────────────
"Did users who started at different times
come back at different rates?"
```

Cohort analysis is essentially a more structured way to analyze retention across different starting groups.
