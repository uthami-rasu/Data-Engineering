# SQL Pattern 14: Trend Analysis

## 1. What Is Trend Analysis?

**Trend analysis** means comparing values over time to determine whether something is:

```text
Increasing
Decreasing
Staying the same
```

For example, suppose monthly revenue is:

| month | revenue |
|-------|--------:|
| Jan | 1000 |
| Feb | 1200 |
| Mar | 1100 |
| Apr | 1500 |

We want to answer:

```text
Did revenue increase or decrease?
By how much?
What is the growth percentage?
What is the overall direction?
```

---

# 2. Problem Statement

Given monthly revenue data, determine:

1. Previous month's revenue.
2. Change from the previous month.
3. Percentage change.
4. Whether the trend is UP, DOWN, or SAME.

---

# 3. Input

## monthly_sales

| month | revenue |
|-------|--------:|
| 2024-01 | 1000 |
| 2024-02 | 1200 |
| 2024-03 | 900 |
| 2024-04 | 1500 |
| 2024-05 | 1500 |
| 2024-06 | 1800 |

---

# 4. Expected Output

| month | revenue | previous_revenue | change | growth_pct | trend |
|-------|--------:|-----------------:|-------:|-----------:|-------|
| 2024-01 | 1000 | NULL | NULL | NULL | N/A |
| 2024-02 | 1200 | 1000 | 200 | 20.00% | UP |
| 2024-03 | 900 | 1200 | -300 | -25.00% | DOWN |
| 2024-04 | 1500 | 900 | 600 | 66.67% | UP |
| 2024-05 | 1500 | 1500 | 0 | 0.00% | SAME |
| 2024-06 | 1800 | 1500 | 300 | 20.00% | UP |

---

# 5. The Core Idea

Trend analysis is usually:

```text
Current Value
      ↓
Previous Value
      ↓
Compare
      ↓
Calculate Change
      ↓
Calculate Growth %
      ↓
Determine Trend
```

The most important function is:

```sql
LAG()
```

because it gives us the previous value.

---

# 6. Step 1 — Get Previous Value

## Problem

Find the previous month's revenue.

### SQL

```sql
SELECT
    month,
    revenue,
    LAG(revenue) OVER (
        ORDER BY month
    ) AS previous_revenue
FROM monthly_sales;
```

---

# 7. Output

| month | revenue | previous_revenue |
|-------|--------:|-----------------:|
| Jan | 1000 | NULL |
| Feb | 1200 | 1000 |
| Mar | 900 | 1200 |
| Apr | 1500 | 900 |
| May | 1500 | 1500 |
| Jun | 1800 | 1500 |

The first row has no previous month, so:

```text
previous_revenue = NULL
```

---

# 8. Step 2 — Calculate Absolute Change

The formula is:

```text
Current Revenue - Previous Revenue
```

For February:

```text
1200 - 1000 = 200
```

For March:

```text
900 - 1200 = -300
```

For April:

```text
1500 - 900 = 600
```

### SQL

```sql
SELECT
    month,
    revenue,

    revenue
    - LAG(revenue) OVER (
        ORDER BY month
      ) AS revenue_change

FROM monthly_sales;
```

---

# 9. Output

| month | revenue | revenue_change |
|-------|--------:|---------------:|
| Jan | 1000 | NULL |
| Feb | 1200 | 200 |
| Mar | 900 | -300 |
| Apr | 1500 | 600 |
| May | 1500 | 0 |
| Jun | 1800 | 300 |

Interpretation:

```text
Positive → Increased
Negative → Decreased
0        → No change
```

---

# 10. Step 3 — Calculate Percentage Change

Absolute change tells us the amount.

Percentage change tells us the relative growth.

Formula:

```text
                 Current - Previous
Growth % = ----------------------------- × 100
                    Previous
```

For February:

```text
(1200 - 1000)
---------------- × 100
     1000

= 20%
```

For March:

```text
(900 - 1200)
-------------- × 100
    1200

= -25%
```

---

# 11. SQL

```sql
SELECT
    month,
    revenue,

    ROUND(
        (
            revenue
            - LAG(revenue) OVER (
                ORDER BY month
            )
        ) * 100.0
        /
        NULLIF(
            LAG(revenue) OVER (
                ORDER BY month
            ),
            0
        ),
        2
    ) AS growth_pct

FROM monthly_sales;
```

`NULLIF(..., 0)` protects against division by zero.

---

# 12. Output

| month | revenue | growth_pct |
|-------|--------:|-----------:|
| Jan | 1000 | NULL |
| Feb | 1200 | 20.00% |
| Mar | 900 | -25.00% |
| Apr | 1500 | 66.67% |
| May | 1500 | 0.00% |
| Jun | 1800 | 20.00% |

---

# 13. Step 4 — Determine Trend

Now classify each month:

```text
Current > Previous → UP
Current < Previous → DOWN
Current = Previous → SAME
```

### SQL

```sql
SELECT
    month,
    revenue,

    CASE
        WHEN LAG(revenue) OVER (
            ORDER BY month
        ) IS NULL
            THEN 'N/A'

        WHEN revenue >
             LAG(revenue) OVER (
                 ORDER BY month
             )
            THEN 'UP'

        WHEN revenue <
             LAG(revenue) OVER (
                 ORDER BY month
             )
            THEN 'DOWN'

        ELSE 'SAME'
    END AS trend

FROM monthly_sales;
```

---

# 14. Output

| month | revenue | trend |
|-------|--------:|-------|
| Jan | 1000 | N/A |
| Feb | 1200 | UP |
| Mar | 900 | DOWN |
| Apr | 1500 | UP |
| May | 1500 | SAME |
| Jun | 1800 | UP |

---

# 15. Complete Trend Analysis Query

Instead of calling `LAG()` many times, it is cleaner to calculate the previous value in a CTE.

```sql
WITH revenue_data AS (
    SELECT
        month,
        revenue,

        LAG(revenue) OVER (
            ORDER BY month
        ) AS previous_revenue

    FROM monthly_sales
)

SELECT
    month,
    revenue,
    previous_revenue,

    revenue - previous_revenue AS revenue_change,

    ROUND(
        (
            revenue - previous_revenue
        ) * 100.0
        / NULLIF(previous_revenue, 0),
        2
    ) AS growth_pct,

    CASE
        WHEN previous_revenue IS NULL
            THEN 'N/A'

        WHEN revenue > previous_revenue
            THEN 'UP'

        WHEN revenue < previous_revenue
            THEN 'DOWN'

        ELSE 'SAME'
    END AS trend

FROM revenue_data
ORDER BY month;
```

---

# 16. Understanding the Complete Flow

Take April:

```text
Current revenue = 1500
Previous revenue = 900
```

### Change

```text
1500 - 900 = 600
```

### Growth

```text
600 / 900 × 100
= 66.67%
```

### Trend

```text
1500 > 900
→ UP
```

So April becomes:

| month | revenue | previous | change | growth | trend |
|-------|--------:|---------:|-------:|-------:|-------|
| Apr | 1500 | 900 | 600 | 66.67% | UP |

# 17. Template 1 — Month-over-Month Growth

This is probably the most common trend-analysis question.

### Problem

Calculate monthly revenue growth.

```sql
WITH data AS (
    SELECT
        month,
        revenue,
        LAG(revenue) OVER (
            ORDER BY month
        ) AS previous_revenue
    FROM monthly_sales
)
SELECT
    month,
    revenue,
    ROUND(
        (revenue - previous_revenue) * 100.0
        / NULLIF(previous_revenue, 0),
        2
    ) AS growth_pct
FROM data;
```

---

# 18. Template 2 — Identify Increasing Months

### Problem

Find months where revenue increased compared with the previous month.

```sql
WITH data AS (
    SELECT
        month,
        revenue,
        LAG(revenue) OVER (
            ORDER BY month
        ) AS previous_revenue
    FROM monthly_sales
)
SELECT
    month,
    revenue,
    previous_revenue
FROM data
WHERE revenue > previous_revenue;
```

Output:

| month | revenue | previous_revenue |
|-------|--------:|-----------------:|
| Feb | 1200 | 1000 |
| Apr | 1500 | 900 |
| Jun | 1800 | 1500 |

---

# 19. Template 3 — Identify Decreasing Months

```sql
WITH data AS (
    SELECT
        month,
        revenue,
        LAG(revenue) OVER (
            ORDER BY month
        ) AS previous_revenue
    FROM monthly_sales

    revenue,
    previous_revenue

```

Output:

| month | revenue | previous_revenue |
|-------|--------:|-----------------:|
| Mar | 900 | 1200 |

# 20. Template 4 — Detect Consecutive Growth

Sometimes the question is:

> Find periods where revenue increased for at least 3 consecutive months.

Example:

| month | revenue |
|-------|--------:|
| Jan | 1000 |
| Feb | 1100 |
| Mar | 1200 |
| Apr | 1300 |
| May | 1000 |

We first determine whether each month increased.

```sql
WITH data AS (
    SELECT
        month,
        revenue,
        LAG(revenue) OVER (
            ORDER BY month
        ) AS previous_revenue
    FROM monthly_sales
)
SELECT
    month,
    revenue,

    CASE
        WHEN revenue > previous_revenue
            THEN 1
        ELSE 0
    END AS increased

FROM data;
```

Then consecutive-growth questions can be solved using the **Gaps & Islands** pattern you already learned.

This is an important connection:

```text
Trend Analysis
      +
Gaps & Islands
      ↓
Consecutive growth periods
```

---

# 21. Template 5 — Compare Current vs Same Month Last Year

Trend analysis is not always:

```text
This month vs previous month
```

Sometimes it is:

```text
This month vs same month last year
```

Example:

| month | revenue |
|-------|--------:|
| Jan 2024 | 1000 |
| Jan 2025 | 1300 |

Growth:

```text
(1300 - 1000) / 1000 × 100
= 30%
```

This is called:

```text
YoY = Year-over-Year
```

For monthly data, you can use `LAG()` with an offset of 12 when the dataset contains every month:

```sql
LAG(revenue, 12) OVER (
    ORDER BY month
)
```

---

# 22. Template 6 — Week-over-Week Growth

Same concept.

```sql
LAG(revenue, 1) OVER (
    ORDER BY week
)
```

Compare:

```text
Current Week
vs
Previous Week
```

---

# 23. Template 7 — Year-over-Year Growth

For annual data:

```sql
LAG(revenue, 1) OVER (
    ORDER BY year
)
```

For monthly data:

```sql
LAG(revenue, 12) OVER (
    ORDER BY month
)
```

assuming the months are complete and correctly ordered.

---

# 24. Template 8 — Trend Per Customer

Sometimes each customer needs an independent trend.

Input:

| customer_id | month | revenue |
|------------:|-------|--------:|
| 1 | Jan | 100 |
| 1 | Feb | 150 |
| 1 | Mar | 120 |
| 2 | Jan | 200 |
| 2 | Feb | 250 |
| 2 | Mar | 300 |

Use:

```sql
LAG(revenue) OVER (
    PARTITION BY customer_id
    ORDER BY month
)
```

Why `PARTITION BY`?

Because we want:

```text
Customer 1
Jan → Feb → Mar

Customer 2
Jan → Feb → Mar
```

Each customer's trend is calculated independently.

---

# 25. Example

```sql
WITH data AS (
    SELECT
        customer_id,
        month,
        revenue,

        LAG(revenue) OVER (
            PARTITION BY customer_id
            ORDER BY month
        ) AS previous_revenue

    FROM customer_sales
)

SELECT
    customer_id,
    month,
    revenue,
    previous_revenue,

    CASE
        WHEN previous_revenue IS NULL THEN 'N/A'
        WHEN revenue > previous_revenue THEN 'UP'
        WHEN revenue < previous_revenue THEN 'DOWN'
        ELSE 'SAME'
    END AS trend

FROM data
ORDER BY customer_id, month;
```

# 28. Common Mistakes

## Mistake 1 — Wrong Ordering

Wrong:

```sql
LAG(revenue) OVER ()
```

You need an ordering column:

```sql
LAG(revenue) OVER (
    ORDER BY month
)
```

Otherwise there is no meaningful previous row.

---

## Mistake 2 — Forgetting `PARTITION BY`

If you need trends per customer, department, product, etc., use:

```sql
PARTITION BY customer_id
```

Otherwise different entities can be compared with each other.

---

## Mistake 3 — Dividing by Zero

This can cause an error:

```sql
(current - previous) / previous
```

Use:

```sql
NULLIF(previous, 0)
```

---

## Mistake 4 — Treating NULL as Zero

The first row has no previous value.

It is usually better to keep:

```text
NULL
```

rather than pretending the previous value was zero.

---

## Mistake 5 — Confusing Absolute Change and Percentage Change

These are different:

```text
Absolute Change
= Current - Previous

Percentage Change
= (Current - Previous) / Previous × 100
```

Example:

```text
Previous = 100
Current  = 120

Absolute change = 20
Growth = 20%
```

---

# 29. Trend vs Rolling Window

These are related but different.

## Trend Analysis

Compares one point with another point.

```text
Current
vs
Previous
```

Usually:

```sql
LAG()
```

## Rolling Window

Looks at multiple previous rows.

```text
Current
+
Previous N rows
```

Usually:

```sql
ROWS BETWEEN N PRECEDING
AND CURRENT ROW
```

Example:

```text
Trend:
Jan → Feb

Rolling:
Jan + Feb + Mar
```

# 30. Trend vs Running Total

### Running Total

```text
How much have we accumulated so far?
```

Uses:

```sql
SUM() OVER()
```

### Trend

```text
Did the value increase or decrease?
```

Uses:

```sql
LAG()
```

```sql

    ORDER BY date
)
```

## Previous N Rows

```sql
LAG(value, N) OVER (
    ORDER BY date
)
```

## Change

```sql
current_value - previous_value
```

## Growth %

```text
(current - previous)
/
previous
× 100
```

## Trend

```sql
CASE
    WHEN current > previous THEN 'UP'
    WHEN current < previous THEN 'DOWN'
    ELSE 'SAME'
END
```

## Per-Entity Trend

```sql
LAG(value) OVER (
    PARTITION BY entity_id
    ORDER BY date
)
```
