# Pattern 8: Deduplication

This is one of the most practical SQL patterns used in ETL pipelines, data engineering, and analytics.

---

# Concept Overview

Deduplication means:

> Multiple records exist for the same entity, but we want to keep only one record.

Examples:

- Keep latest order per customer
- Keep latest address per user
- Remove duplicate events
- Keep first transaction per account

---

# Problem Statement

Keep only the latest record for each customer.

---

# Input

## customer_orders

| customer_id | order_id | order_date |
| ----------- | -------- | ---------- |
| 1           | 101      | 2024-01-01 |
| 1           | 102      | 2024-01-10 |
| 1           | 103      | 2024-01-20 |
| 2           | 201      | 2024-01-05 |
| 2           | 202      | 2024-01-15 |

---

# Expected Output

| customer_id | order_id | order_date |
| ----------- | -------- | ---------- |
| 1           | 103      | 2024-01-20 |
| 2           | 202      | 2024-01-15 |

---

# Core Idea

Assign a rank within each customer.

```sql id="1"
ROW_NUMBER() OVER(
    PARTITION BY customer_id
    ORDER BY order_date DESC
)
```

---

# Step-by-Step

### Customer 1

| order_id | order_date |  rn |
| -------- | ---------- | --: |
| 103      | Jan20      |   1 |
| 102      | Jan10      |   2 |

Keep:



# Template 1: Keep Latest Record

## SQL

```sql id="4"
WITH ranked AS (
    SELECT
        *,
        ROW_NUMBER() OVER(
            PARTITION BY customer_id
            ORDER BY order_date DESC
        ) AS rn
    FROM customer_orders
)
SELECT *
FROM ranked
WHERE rn = 1;
```

---

# Template 2: Keep First Record

## Problem Statement

Keep the earliest order for each customer.

### SQL

```sql id="5"
WITH ranked AS (
    SELECT
        *,
        ROW_NUMBER() OVER(
            PARTITION BY customer_id
            ORDER BY order_date ASC
        ) AS rn
    FROM customer_orders
)
SELECT *
FROM ranked
WHERE rn = 1;
```

| ----------- | -------- |
| 1           | 101      |

# Template 3: Remove Exact Duplicates

## Input

| user_id | email                           |
| ------- | ------------------------------- |
| 1       | [a@test.com](mailto:a@test.com) |
| 1       | [a@test.com](mailto:a@test.com) |
| 1       | [a@test.com](mailto:a@test.com) |
| 2       | [b@test.com](mailto:b@test.com) |

---

## SQL

```sql id="6"
WITH ranked AS (
    SELECT
        *,
        ROW_NUMBER() OVER(
            PARTITION BY user_id, email
            ORDER BY user_id
        ) AS rn
    FROM users
)
SELECT *
FROM ranked
WHERE rn = 1;
```

---

# Output

| user_id | email                           |
| ------- | ------------------------------- |
| 1       | [a@test.com](mailto:a@test.com) |
| 2       | [b@test.com](mailto:b@test.com) |

---

# Template 4: Delete Duplicates

## PostgreSQL

```sql id="7"
DELETE FROM users
WHERE id IN (
    SELECT id
    FROM (
        SELECT
            id,
            ROW_NUMBER() OVER(
                PARTITION BY email
                ORDER BY id
            ) AS rn
        FROM users
    ) t
    WHERE rn > 1
);
```

# Template 5: Latest Status Per User

| ------- | -------- | ---------- |

## SQL

```sql id="8"

    SELECT
        *,
        ROW_NUMBER() OVER(
            PARTITION BY user_id

        ) AS rn
    FROM user_status

SELECT *
FROM ranked
WHERE rn = 1;
```

# Common Mistakes

### Mistake 1

Using:

```sql id="13"
DISTINCT
```

instead of proper deduplication.

Example:

```sql id="14"
SELECT DISTINCT *
```

This only removes identical rows.

It cannot answer:

> Keep the latest row per customer.

---

### Mistake 2

Missing `ORDER BY`.

```sql id="15"
ROW_NUMBER()
OVER(PARTITION BY customer_id)
```

Without ordering, "latest" or "first" is undefined.

# Recognition Guide

When you hear:

- Latest record
- First record
- Remove duplicates
- Latest status
- Latest order
- Latest address

Think:

```sql id="16"
ROW_NUMBER()
OVER(
    PARTITION BY entity
    ORDER BY timestamp DESC
)
```

Then:

```sql id="17"
WHERE rn = 1
```
